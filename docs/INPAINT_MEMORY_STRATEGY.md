# 修补内存策略

自动翻译的复杂背景擦字与精修页的背景修补统一使用 `MangaLama` 的分块策略。该策略适用于图片和每一张 PDF 页，无需手动切图或改变 PDF DPI。

1. 空蒙版跳过模型。小范围修补只提取蒙版及周边上下文。
2. 较大范围以原始像素切块，单次模型输入默认不超过 768×768；按需补齐到 8 的倍数后也不超过上限。无待修补像素的块跳过。
3. 每块保留周边上下文，相邻输出区域重叠并加权融合。只替换蒙版覆盖的像素，原页尺寸、未修补区域保持不变；文字排版仍在整页坐标中进行。
4. 融合缓存按水平带处理，不创建整页的浮点 RGB 累加缓冲。
5. 识别到内存分配失败时，当前页从原图按 512、384、256 像素上限依次重试；该模型实例的后续页面沿用成功的较小块。其他错误正常上报。
6. 最小块仍无法运行时提示释放占用或改用 CPU，再通过断点续传继续。已完成的页、已保存译文保留，失败页不会保存半张修补结果。自动翻译可在块之间响应停止。

保留清晰度是硬约束：不缩小页面或修补输入图，不自动降低 PDF DPI；内存不足只缩小每次处理的像素范围，不能通过降采样兜底。页面中间文件使用 PNG，合成及更新 PDF 时无损嵌入完整像素的页图，避免额外 JPEG 压缩。PDF 写入器的 72 DPI 仅定义页面坐标，不代表把页图降为 72 DPI。

上述保证以进入修补流程的页图为基准。PDF 导入仍按所选 DPI 光栅化，不保留矢量对象；蒙版内属于模型重绘，不能保证还原被文字遮挡的原背景。更小块会增加推理次数、减少可见上下文，大面积连续纹理的修补效果仍需要精修检查；分块可限制单次模型输入，但不能保证在任意可用内存下运行。翻译请求保持不变。

修改 Python 源码后需重启客户端，让已加载的模型实例采用新策略。使用相同原文件、输出目录、翻译配置并保持“断点续传”开启，可继续已有任务，无需清除精修资料或断点记录。

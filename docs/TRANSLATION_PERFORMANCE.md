# PDF 翻译性能：2026-11-02 实测与修复

本页记录翻译流水线的耗时。[精修性能](EDITOR_PERFORMANCE.md) 中的项目打开、切页和保存测试不代表 PDF 翻译速度。

## 本次慢在哪里

100 页 PDF，每页 3928×5556，配置 200 DPI。本地日志显示：

- 15:47:02 开始，15:51:09 才渲染完全部页图：首次翻译前等待 247 秒。
- 前四页检测与 OCR 约 8 秒，API 并发请求约 2 秒。
- 前三页背景修补分别约 106、80、75 秒。
- 在同一环境复现：请求 CUDA 后会话实际只有 CPU。运行库缺少加载步骤，找不到 `cublasLt64_12.dll`；“可用提供者包含 CUDA”不能证明会话启用了 CUDA。
- 第一页另有大字掩膜瓶颈，两次高斯滤波合计约 31 秒。

## 改动

`onnx_session.py` 统一模型会话创建。在申请 CUDA 前，调用 ONNX Runtime 提供的运行库预加载入口，随后记录会话实际使用的设备；CPU 回退会明确提示。CPU 模式不会探测或预加载 CUDA。这个步骤独立于错误报告，也不会导入 PyTorch。[ONNX Runtime 官方说明](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html#preload-dlls)

PDF 建立任务时只读取页数和物理尺寸。在途页数上限内按需渲染对应页图，不再等待整本转换完成；同一本书复用已打开的 PDF，结束、出错或取消时释放。有效的原尺寸 PNG 缓存继续使用，缺失、损坏或尺寸错误的缓存按页重建。写入先暂存，成功且未取消后再替换，保持原有 DPI 和无损 PNG。

大尺寸背景估计滤波保持高斯核范围、8 位系数量化、边界规则和输出舍入，通过分离卷积的 DFT 实现加速；图像不缩放。2685×1647×3 的实际文字块与旧滤波输出逐通道比较，差异数为 0。独立随机图、窄条和边界测试也逐像素比较旧实现。[OpenCV 高斯核实现](https://github.com/opencv/opencv/blob/4.x/modules/imgproc/src/smooth.dispatch.cpp)

日志增加每页 PDF 页图准备、检测/OCR、修补/嵌字/保存的耗时，方便区分本地推理和 API 等待。

## 连续流水线与负载重叠

原调度先准备一批页面，等本批所有 API 返回，再逐页修补；这一批全部结束才准备下一批。现在 `PagePrefetch` 持续准备后续页，每页准备好就提交 API，当前页译文返回后立即进入修补，不等待其他页译文。结果仍按输入顺序保存。

`max_workers` 同时限制所有在途页（包括正在修补的页），默认 4。完成一页才释放一个名额并补入下一页，已处理图像及时释放。设置为 1 时顺序执行；不是把整本 PDF 或每一页各自放进无限队列。

CPU 预处理、PDF 渲染和网络等待可以与修补重叠。检测、OCR、LaMa 若实际使用 CUDA，则通过公平队列逐次推理：检测/OCR 可在 LaMa 分块之间获得执行机会，减少同时推理的资源争用。这个策略不改尺寸、掩膜、模型精度、修补分块或输出编码；同一 GPU 的计算瓶颈仍存在，吞吐量不会简单随并发数成倍增加。

准备上下文和修补上下文共用已加载的模型，但分别保存页掩膜及 OCR 状态。PDF 原生资源在准备线程内创建、使用和释放。检查点保存加锁，避免 API 回包与完成记录同时落盘时相互覆盖；取消或全局 API 错误会停止预取，已发出的合法译文仍可缓存以供续传。

### 离线对照

同一设备、同三页 3928×5556 原图，预热首张后对照原批次调度与新流水线；两者并发上限均为 4。实际执行图片读取、检测、OCR、修补、嵌字、保存及检查点。使用已存译文，每次 API 调用模拟等待 2 秒，无远程请求和费用。此处不包含 PDF 渲染、模型初始化或最终 PDF 合成。

| 调度 | 三页总耗时 | 首张完成 |
|---|---:|---:|
| 原批次调度 | 42.43 秒 | 23.12 秒 |
| 连续流水线 | 37.85 秒 | 18.69 秒 |

这次总耗时减少约 10.8%，首张提前约 19.2%。两种调度的输出解码后逐像素一致。单次离线对照不是整本 PDF 的实际 API 测速；收益随 API 延迟、页内容、设备负载及缓存状态变化。[原始记录](ui-review/page-overlap-performance.json)

```powershell
.venv\Scripts\python.exe scripts/benchmark_page_overlap.py "项目资料目录" --pages 1 2 3 --api-delay 2 --json tmp/overlap-benchmark.json
```

新增回归覆盖：首张无需等待整批、在途容量与图像释放、提前退出时线程和 PDF 资源清理、GPU 排队与取消、页状态不串扰、取消保留在途译文、账户错误停止后续页，以及并发检查点完整性。

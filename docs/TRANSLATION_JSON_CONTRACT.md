# 翻译 API 的 JSON 输出约定

本轮将翻译请求、格式校验与兼容协商从图像流水线中拆出。`ComicTranslatorPipeline.translate_page_batch()` 保留原调用方式，委托给 `comic_translate_core/translation.py`。每次请求使用不可变的 `TranslationSettings` 快照，运行期间的后续设置变化不会改变本次续译的参数。

## 输出与校验

```json
{"translations": ["第一条译文", "第二条译文", ""]}
```

- 顶层只能有 `translations`，且必须为字符串数组。空译文使用 `""` 占位。
- 数量与当前请求的原文条数严格一致，顺序由原文编号和提示词约束；本地无法判断语义上是否调换顺序。
- 拒绝数字、布尔值、`null`、对象、额外字段、重复字段、无效 Unicode 和 JSON 前后的解释文字。不会强转类型、裁掉多余结果或静默补空。
- 兼容完整包裹 JSON 的 Markdown 代码围栏，仅剥离外层围栏，不改动译文字符串内的反引号、换行、引号或反斜杠。
- API 结果和写入续传缓存、进入擦字嵌字前均有校验。已有布局文件格式不变。

## 接口兼容

优先请求 `response_format.type=json_schema`，开启 `strict`，要求必填的字符串数组、禁止额外字段，设置精确的 `minItems` / `maxItems`。服务端明确拒绝相关参数时，依次退回 `json_object` 和仅提示词约束；**所有模式都执行同一套本地校验**。服务端的 JSON Schema 支持范围参考 [OpenAI 结构化输出文档](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)。第三方兼容接口以其实际参数响应为准，不根据模型名称硬编码。

能力降级在当前流水线实例内按 Base URL、模型名记忆，避免每页重复尝试已拒绝的格式。不持久化密钥或接口能力；重建流水线或重启后会重新探测。401、429、5xx 等鉴权、限流和服务错误不会触发格式降级。图片上下文、思考参数和 token 参数的兼容回退分别处理。

每次内容请求最多执行 6 次参数协商（最多 5 次分别移除不支持的选项，最后一次请求）；内容校验最多 3 轮。SDK 对临时网络错误仍保留原有的最多 2 次重试。连续失败会明确报错并停止该页，不生成看似成功的空白译图。

## 截断、拒答与取消

只有服务端标记 `finish_reason=length` 且响应为语法正确的字符串数组前缀，才保留已完整返回的条目并续译后缀。后续请求保留全页原始编号，并更新 Schema 数量。完整 JSON 数量不符时，无法判断漏了哪个位置，因此重试当前整组。缺少闭合符但条目已够数也会重试，避免将损坏的结果直接交给排版。

模型拒答或内容过滤会明确报错。取消会阻止后续请求；若在途请求已返回完整、校验通过的译文，允许保存进续传缓存，后续图像处理仍停止。网络请求本身使用现有超时，取消不会强行中断已经发出的 HTTP 请求。

## 可独立测试的边界

- `translation_format.py`：协议、解析、类型与数量校验、格式能力记忆，无 Qt 或模型依赖。
- `translation.py`：请求与有限重试，注入 API 客户端、简繁转换、进度和取消回调。
- `pipeline_settings.py`：任务快照及桌面、后台复用的运行配置更新。
- `page_store.py`：自动处理和精修共同使用的文件暂存与失败回滚。

测试通过模拟接口覆盖 Schema、兼容降级、截断、拒答、取消与错误响应，不会调用用户配置的付费接口。原始分辨率不变。文件回滚保护正常进程内的异常，不宣称提供断电后的多文件事务恢复。

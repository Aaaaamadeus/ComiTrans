# ComiTrans 优化执行计划（2026-08-07）

## 总则
- 每步完成做自我审查（编译/逻辑验证/回归），通过后提交 git，便于随时回滚。
- 三个任务互不依赖，顺序执行。

## 任务 1：新增输出目录设置（默认输出路径不变）
- 现状：输出目录设置已存在于 API 配置页，默认 `page/output_page_output`。
- 改动：在翻译页顶部新增“输出目录”设置行（输入框 + 浏览按钮），默认值读取现有 `page_output_dir`，修改后立即更新配置并用于本次翻译输出。
- 审查：源码编译、config 读写、UI 逻辑；保持默认路径不变。
- 提交：`feat: add output dir setting on translation page`

## 任务 2：补齐指定图标并优化 UI 审美
- 现状：exe 使用 `assets/ComiTrans.ico`，但窗口/按钮没有图标，整体样式简单。
- 改动：
  1. 主窗口设置窗口图标（源码和打包版都指向 ComiTrans.ico）。
  2. header 主要按钮补充图标（Qt 标准图标），统一按钮尺寸与 hover 样式。
  3. 优化整体样式表：间距、tab、group、列表的观感。
  4. 打包配置把 ico 加入 datas，保证打包版窗口图标可用。
- 审查：源码运行界面逻辑、spec 配置、字体/布局不回归。
- 提交：`feat: use app icon across ui and polish styles`

## 任务 3：多图处理时间压缩（API 请求并行）
- 现状：worker 逐图串行，每页一次翻译 API 请求，网络等待是主要耗时。
- 改动：
  1. pipeline 拆分为 `prepare_comic_page`（读图+检测+OCR）、`translate_page_batch`（不变）、`finish_comic_page`（修复+嵌字+保存）。
  2. worker 先串行 prepare 所有图片，再并发发起各页翻译请求（ThreadPoolExecutor，默认 4 并发，受 `max_workers` 配置控制），最后串行 finish。
  3. 保留取消与进度信号；翻译失败保持原有降级行为。
- 审查：源码编译；用无 API Key 场景验证降级；多图流程逻辑走查；打包版预热不回归。
- 提交：`perf: parallelize page translation api requests`

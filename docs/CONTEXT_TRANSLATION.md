# 上下文理解翻译

上下文理解是翻译流程的固定行为。每页请求同时提供本页全部 OCR 文本和已确认的前文原文/译文，用来理解指代、角色关系、语气与情节，并统一人名、称呼和术语。用户的人名对照与背景要求优先。文本模式、多模态模式和模型不支持图片时的回退均使用同一份前文；格式降级与截断续译不会丢失上下文，也不会把未通过校验的响应写入缓存。

`retain_translation_context` 默认关闭，只控制跨任务是否沿用前文，不控制上下文翻译本身：

- 任务开始时读取配置快照一次。关闭时先清空前一任务的上下文，再执行本次任务；同一任务内的图片与 PDF 页始终共享前文。
- 开启时沿用缓存，且强制 `resume_enabled=true`。界面锁定断点续传勾选，后端也独立保证这一约束。
- 任务中不再检查开关。成功译文校验、字形转换后立即保存译文断点及上下文，不等待修补或输出成功。取消期间收到的有效付费响应同样保存。
- 关闭开关、翻译结束、翻译失败或取消都不会清除已有上下文文件；只有下一次任务开始且开关关闭时才清空。

缓存保存在程序目录 `.cache/translation-context.json`，包含原文、译文、源/目标语言及不可逆页面标识，不保存 API 密钥、请求参数或页面图片。跨目标语言/源语言的条目不会注入当前请求。缓存保留最近最多 12 页、24,000 个序列化字符，每条原文/译文最多 2,000 字符，按完整原文/译文对裁剪；这是有限的滚动前文，不是无限历史或服务端会话。文件通过临时写入、fsync 和原子替换保存。

续传页按阅读顺序重放已保存原文/译文，无需重复 OCR 或 API 请求。清空后可据此重建本任务前文。缓存代际标识记录在译文断点里，沿用缓存时不会把早已读过的旧章节重新追加到最新剧情后。旧版无上下文翻译的断点因翻译协议版本变化而失效。

## 分叉与汇合

```text
检测 / OCR ─┬─ 按阅读顺序翻译 → 校验 / 字形转换 → 保存译文与刷新上下文 ─┐
            └─ 独立页面状态 → 掩膜生成 / 背景修补 ────────────────────┴─ 嵌字 / 原子保存
```

两支在同一页 OCR 完成后立即启动，即使只允许一页在途也能并行。翻译 API 单独按阅读顺序执行，修补使用独立线程与页面状态，下一页检测/OCR 仍可预取。GPU 运算沿用已有推理门禁交错执行，避免工作区竞争。修补支不写最终文件；翻译失败时丢弃临时修补结果，修补失败时已校验译文仍可在续传时复用。

若模型将部分 OCR 条目翻译为空，汇合时按实际非空译文重建精确修补掩膜，避免预修补影响应保留的原文或周围像素。嵌字、导出算法及输出文件格式保持原有行为。

# 界面密度与次级菜单评估

日期：2026-11-22。范围：以下内容为菜单合并前的界面密度评估。

后续更新：用户已要求合入 `optimize_ui_menu_layout` 工作区对应的 `feat/ui-menu-layout`。分支合并、新功能菜单适配与验收已完成；本文件保留合并前的观察，当前入口与交接状态见 [菜单布局交接](UI_MENU_LAYOUT_HANDOFF_2026-11-22.md)。

## 结论

自动处理页仍适合当前的任务流程；嵌字精修页已经偏密，1024 及以下宽度应优先规划次级菜单和按选择状态显示的工具。当前可以完成操作，但继续平铺新增按钮会进一步压缩画布和译文编辑空间。

本次增加多选与样式刷、作品术语库、试译与消耗报告。术语编辑和报告使用独立对话框，主页面增加紧凑入口；新增样式按钮放入现有“排版与位置”页签，避免继续占用译文页签高度。原有功能入口保持所在分区。后续菜单方案尚未实施。

## 观察依据

使用真实 Qt Widgets 渲染检查浅色、深色，以及 1440×900、1024×720、820×640 三种尺寸；另检查原有 820×480 布局。截图过程隔离配置与用户数据，没有调用付费 API。英文和日文额外检查新增对话框。

- 自动处理页的主要顺序仍是队列、翻译方向、开始处理、结果检查。术语库放在偏好中，试译和消耗放在开始按钮附近，任务入口仍能辨认。
- 精修页同时存在导航栏、视图工具、九个快捷字体槽、背景工具、气泡操作、样式刷、文本列表和属性面板。操作分散在多条横向区域，功能层级较平。
- 1024 宽度下，背景工具会分成多行，画布与右侧检查器争夺空间；820 宽度下，页面栏收起后画布仍较窄，原文和操作按钮占据较多纵向空间。在 820×640 中译文输入区域的可视高度已经不足，应列为下一次布局整理的优先验收项。
- 字体库、字体导入、设置快捷字体同时常驻，与频繁切换字体、修改字号的操作混在一起。
- 全局中文人名设置与作品术语库存在一定概念重叠。术语库已经支持只填固定译名，由 AI 根据上下文匹配；后续需要进一步明确“通用默认”和“当前作品”的关系。

轻量测量记录中，自动处理页约有 15 个可见文字按钮，精修页约有 24–27 个；该计数受当前页面、折叠状态、工具是否显示等因素影响，仅用于比较层级密度，不作为可用性评分。

## 后续分组建议（待实施）

| 分区 | 保留直达的常用操作 | 可进入次级菜单的操作 |
|---|---|---|
| 任务 | 开始、停止、试译、当前进度 | 消耗详情、输出位置、任务相关设置 |
| 文件与导出 | 保存、导入页面 | 导出 PDF、打开输出目录、关联原图 |
| 视图 | 适应页面、缩放、当前选择 | 连续长条、面板显隐、专注模式、缩放工具切换 |
| 字体与样式 | 字体选择、字号、排向、当前多选状态 | 字体库、导入字体、快捷字体管理、变形与描边高级选项 |
| 背景修补 | 当前工具、执行、撤销 | 填白、填黑、自定义填色、取色等工具选择 |
| 作品偏好 | 当前作品摘要 | 术语管理、背景设定、通用人名设置 |

气泡右键菜单适合提供取样式、应用样式、还原等与当前气泡直接相关的操作。批量操作继续显示选中数量，明确哪些属性会应用到多个气泡；已还原原图的气泡保持受保护。

建议先整理字体管理与视图操作，再考虑修补工具组；字号、译文编辑和保存继续直达。使用任务含义明确的分组名，每组维持一层次级菜单，配合快捷键提示。

## 后续验收标准

1. 同样三个宽度和浅色/深色分别复查；英文、日文检查标签换行与菜单宽度。
2. 保存、翻译、译文编辑和字号修改均可直接到达。
3. 切换工具或收起面板保留当前文本、选区、缩放与未保存状态。
4. 次级菜单的引入不改变翻译、擦字、排版或导出结果。
5. 用长篇项目实际比较操作路径与画布面积，再决定是否继续收纳其他入口。
